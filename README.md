# 问询回复检索

把一份问询函里的问题粘进来，找出**别的公司被问过的同款问题**，直接去看它们怎么答。

不是语义搜索，也不是 RAG —— 是**逐字级的字符匹配**。原因很简单：问询函里的问题，
差几个字意思就南辕北辙（"存货跌价准备计提是否充分" 和 "存货跌价准备转回是否合理"
在向量空间里很近，在监管逻辑里是两回事）。

---

## 它解决什么问题

写问询回复时最费时间的不是"想怎么答"，而是"**这道题别人答过没有、答成什么样**"。

问询函的问题高度模式化：同一类问题，几十家公司的措辞几乎一样。所以只要把历史问询函
拆成"最小问题单元"，用字符相似度去撞，就能把一个问题的**同题历史答案**一次性捞出来。

```
自家问询函的一个问题
        │
        ▼  4-gram 逐字匹配 + IDF 加权 + 覆盖度
   ┌─────────────────────────────────────┐
   │ 尚水智能 r1 问题12  0.838  ★ 全文逐字命中 │
   │ 高特电子 r1 问题12  0.812                 │
   │ 博科测试 r1 问题11  0.795                 │
   └─────────────────────────────────────┘
        │
        ▼
   点开就是对方回复里对应的那一页
```

## 快速开始

### 方式一：直接用现成的（推荐）

下载离线包（Windows 10/11），解压到桌面或 D 盘，双击 `启动.bat`，浏览器自动打开。

> 发布包见仓库的 Releases / 作者主页。首次启动会在本机建索引（约 6 秒），全程不联网。

### 方式二：从源码跑

```powershell
# 需要 Python 3.10+
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m src.server --open
```

浏览器打开 <http://127.0.0.1:8765>。

> 源码仓库**不带数据**（索引库几百 MB，不适合放 git）。没有 `data/queries.db` 时，
> 页面能打开但搜不出东西 —— 可以先看"自己构建索引"那一节。

### 自己构建索引

把问询函 PDF 按 `公司_r轮次.pdf` 命名，放进按板块分好的子目录（`问询函/北交所/`、`问询函/新三板/`、
`问询函/创业板/`、`问询函/深主板/`、`问询函/科创板/`、`问询函/沪主板/`），然后：

```powershell
.\.venv\Scripts\python.exe -m src.build_db --db data/queries.db --rebuild --jobs 6
```

**想要更快的检索（可选）**：检索内核另有一版 Rust 实现，装了 Rust 工具链就能用：

```bat
cd rust\search-core
cargo build --release
target\release\search-core.exe --build-index ..\..\eval\search.index --db ..\..\data\queries.db
```

没装 Rust、没建索引都不影响使用——`src/engine_rust.py` 找不到内核会自动回退 Python，
只是每次检索约 0.5 秒而不是 0.03 秒。想强制用回 Python：设环境变量 `QB_ENGINE=py`。

`src/pdfread.py` 负责把 PDF 还原成带页码的行，`src/extract.py` 负责切出"最小问题"。
支持两类文档：

- **问询函本身**（问题单独成文）；
- **问询与回复**（交易所只公开回复时，回复里通常把原问题整段抄了一遍，可以从回复里回溯）。

## 功能

- **整段粘贴**：把自家问询函里一整段贴进去，内部先拆成多个最小问题，再按「你的第①问 /
  第②问」分组展示，分组标题完整显示不截断。
- **整份函上传**：把刚收到的问询函（pdf / docx / txt）直接拖进页面（或用左边的
  「上传整份函」），自动拆题、逐个小问检索，分组标题带「题N · 小问K」。
  一份 6 题 / 81 小问的新三板函约 3 秒出结果。
- **板块 / 轮次筛选**，改任一条件自动重搜。
  （章节不提供筛选：创业板/深主板的回复文件里没有章节，抽出来的全是「核查意见」这类
  答案小标题；只有北交所/新三板是真的章节，所以一律按「全部章节」口径搜。）
- **落点面板**：把你的问题按「逐字命中 / 仅 2 字级 / 无对应」三档画出来，一眼看出
  哪几个要求库里没人提过。
- **所有**逐字重合片段都标黄（不只是最长那一段），附原文页码与提问主体。
- 点一下展开"这家公司这个问题的全部小问"。
- 浅色 / 深色主题跟随系统；左侧栏宽度可拖动，记在本地。
- **参考答案指引**：手上有新收到的问询函时，直接让它拆题、逐小问检索、汇总成一张表（见下）。

### 参考答案指引（给"要写回复"的人用）

```bat
.venv\Scripts\python.exe -m scripts.make_guide --pdf 新收到的函.pdf
.venv\Scripts\python.exe -m scripts.make_guide --docx 某函.docx --top 5 --md
```

产出 `out/<函名>_参考答案指引_<日期>.xlsx`，三张表：

| 表 | 内容 |
| --- | --- |
| 指引 | 一道题一块，一行一个小问，右边并排 5 条参考（出处 + 相似度档 + 撞上的问法） |
| 明细 | 一行一条参考，可按板块/公司/档位筛选 |
| 说明 | 语料覆盖、门槛与分档含义、怎么用 |

**它只给定位，不给答案摘要**：哪板块、哪家公司、第几轮、第几题、第几页，
以及库里那家是怎么问的。答案要人自己翻原文——问询回复要严谨，这一层不能偷懒。
明细表最后一列直接给了 PDF 相对路径。

一份 14 题 / 127 小问的函大约 20 秒出表。相似度是 4-gram 逐字比对，
分档 高 ≥0.60 / 中 0.42–0.60 / 弱 0.30–0.42 / 逐字（语料里有逐字相同的提问）；
没到门槛的小问会写明"最像的只有 0.xx"，不会假装没数据。

## 检索是怎么算分的

| 项 | 权重 | 说明 |
| --- | --- | --- |
| 4-gram IDF 加权相似度 | 0.70 | 余弦与覆盖度各占一半；用全库文档频率把"企业会计准则""是否符合"这类满库都是的短语自动降权 |
| 最长公共子串 / 短者长度 | 0.20 | 保证"逐字命中一整句"的一定排在前面 |
| 同问题号 | 0.05 | 同一编号的问题通常问的是同一件事 |
| 同章节 | 0.05 | 章节是弱先验（只有北交所/新三板有真章节，前端已不暴露这个筛选） |

再加两条规则：

- **套话降权**（×0.55）："核查上述事项并发表明确意见"这类跨公司 100% 命中的模板句；
- **句内最优**：一个问题里往往只有一句是你真正想找的，取分句最高分而不是整段平均分。

候选集先用 FTS5 trigram 索引粗筛，再对候选算全分，最后按最长公共子串预算收敛。

同一套算法有两份实现，**打分公式逐条对齐**：

| | Python（默认回退） | Rust 内核（有则优先） |
| --- | --- | --- |
| 候选 | FTS5 trigram 粗筛 6000 条 | 自建 4-gram 倒排索引，全部命中 |
| 出分 | 逐条算余弦 + 覆盖度 | 逐 gram 累加 `acc[doc] += (c·w)·w·tf` |
| 端到端 | 约 0.6 秒 | 约 0.04 秒 |

换掉粗筛结构比换语言更重要：中位查询命中 7.8 万条，FTS5 的 bm25 光排序取 6000 条
就要 0.14~0.29 秒。Rust 内核不做"排序取前 N"，而是把分数累加出来。

改检索逻辑时**必须跑对照集**：`eval/make_golden.py` 在你自己库上抽 200 条真实查询、
用 Python 引擎存下 top-10 当参照物；`eval/compare.py` 再拿另一份实现的结果去比，
给出"每一名的分数都不低于参照"的比例——掉下 100% 就是漏候选或截断窗口设错。
注意参照物必须由 **Python 引擎**生成（`QB_ENGINE=py`），否则等于自己跟自己比。

完整的公式、参数、实测数字和已知局限见 **[docs/算法说明.md](docs/算法说明.md)**。

## 目录

```
src/
  pdfread.py      PDF → 行（只做坐标还原，不依赖字体名）
  normalize.py    归一化（strict 保留数字 / loose 去数字 / core 去法规引用）+ 套话判定
  extract.py      问询函 → 最小问题（章节 / 问题节 / 小问 / 提问段）
  schema.sql      建表语句
  build_db.py     扫描目录 → 抽取 → 入库 → 建索引
  qc.py           入库质量自检（8 项）
  search.py       检索与排序（分发：Rust 内核可用就走它，否则自己算）
  engine_rust.py  Rust 内核的客户端（独立进程，启动失败/出错自动回退）
  server.py       FastAPI 服务（单页前端，无构建步骤）
  webui/index.html
rust/search-core/ Rust 检索内核：4-gram 倒排索引 + IDF 加权打分（可选加速）
eval/             对照集与验收脚本（make_golden.py / compare.py）
scripts/          建库、导出公开仓库、基准测试、PDF 修复、参考答案指引等工具
deploy/           容器化部署 + Cloudflare 隧道
pack/             离线发布包生成器
docs/部署指南.md   怎么给同事用：本机 / 局域网 / 固定网址 / 服务器
```

## 数据说明

- 语料来自**沪深北交易所公开披露的审核问询函及其回复**。
- 本项目只做**解析与检索**，不包含任何抓取逻辑，也不随仓库分发原始 PDF 或索引库。
- 检索结果仅供学习与研究参考，**不构成审计意见、投资建议或任何形式的专业结论**；
  准确性、完整性以交易所原始披露文件为准。
- 如权利人认为本项目的处理方式不妥，请联系删除。
