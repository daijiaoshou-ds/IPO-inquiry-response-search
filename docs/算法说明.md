# 问询回复检索 · 算法说明

> 一段问询函文字输进去，在 20 万条历史问题里，为什么某一条排第一。
> 本文只讲检索与排序，不涉及数据来源与入库流程。

适用版本：2026-10 · 语料：4,306 份问询函 / 回复，279,335 条最小 query

---

## 0. 一句话

把每句话切成 **4 字碎片**，每个碎片按"全库有多少人这么写"给一个权重；
两句话各自把碎片权重**平方求和**，得到自己的分量；
再算两个比值——**余弦**（两边都进分母）和**覆盖度**（只有提问方进分母）——
最后加上整句逐字重合的加分、套话的罚分，就是这条结果的分数。

下面逐步展开，所有数字都是这个库里实测的。

---

## 1. 要解决的问题

- **输入**：用户粘一段自家问询函的问题（可能一整段，含好几个要求）。
- **输出**：别的公司被问过的同款问题，按"有多像"排序。
- **难点**：要找的不是"原文"，而是"同一个要求的不同写法"。

同一个要求，各家公司的问法差得很远：

```
A: 说明报告期各期末存货跌价准备的计提方法、计提依据及充分性
B: 请发行人说明存货跌价准备计提是否谨慎、充分，与同行业可比公司是否存在差异
```

A 和 B 问的是同一件事，但没有一个字面意义上的"关键词表"能覆盖这种改写。

### 为什么不用语义向量

有三条理由，按重要性排：

1. **问询函是制度性语言。** "研发人员认定标准""替代程序的具体情况""是否存在体外资金循环"——这类表述跨公司、跨年份高度复用，**字面重合本身就是强信号**。用语义模型反而丢掉了这个最可靠的信号。
2. **可解释。** 读者最常问的是"为什么这条排第一"。本方案能给出：这条结果的每一个重合碎片、它的权重、它在两句话里的位置。向量模型给不了。
3. **成本。** 一次检索 0.5 秒内，不需要 GPU，离线包里一个 40 MB 的 Python 环境就能跑。

---

## 2. 数据单位：最小 query

一封问询函不是"一条"，它有层级：

```
问询函
 └─ 章节（一、基本情况 / 二、业务与技术 / …）
     └─ 问题节（问题 1、问题 2 …）
         └─ 最小 query（一个"要求"）
```

一条最小 query 大约 40~120 字，只包含**一个可以单独回答的要求**：

```
问题 7：关于存货跌价准备
  ① 说明报告期各期末存货跌价准备的计提方法、计提依据及充分性；
  ② 说明与同行业可比公司存货跌价准备计提比例的差异原因。
```

拆到这个粒度是必须的：用户的问题里往往也含好几个要求，粗粒度的"整封函"没法匹配。

当前库：**4,306 份**文件、**2,636 家**公司、**57,631 个**问题节、**279,335 条**最小 query，覆盖 6 个板块。

## 3. 归一化：同一段文字存三份

| 字段 | 处理 | 用途 |
| --- | --- | --- |
| `raw_text` | 原文不动 | 展示、标黄定位 |
| `norm_strict` | 全半角统一、去空白、去标点，**保留数字** | 精确子串命中、页码定位 |
| `norm_loose` | 在 strict 基础上**再去数字** | 建倒排索引、粗筛 |
| `norm_core` | 在 loose 基础上**再清掉法规 / 准则引用** | **算权重和打分** |

### 为什么要专门清掉法规引用

"是否符合《企业会计准则》的规定"这类表达，对"找同款问题"零区分度，却实实在在推高两条无关问题的相似度。

麻烦在于：它的**文档频率并不高**（每家引用的准则名、条款号都不一样），所以 IDF 会给它一个**不低**的权重——等于给噪声发奖金。所以不能靠 IDF 解决，必须在算权重之前**物理删掉**：

```
企业会计准则 / 企业会计准则第 X 号 / 公司法 / 证券法
公开发行证券的公司信息披露内容与格式准则第 X 号
是否符合相关法律法规的规定 / 符合相关规定 / 是否符合规定 …
```

注意反向的坑：**不能顺手删"说明""核查""是否"这类词**。它们在问询函里到处都是，但位置决定作用——"说明"开头的追问和"是否"引导的判断，是问题结构的一部分。这类高频通用词交给 IDF 连续降权就好，不要用停用词表硬删。

### 一个真实例子

```
原文      说明报告期各期末存货跌价准备的计提方法、计提依据及充分性
norm_core 说明报告期各期末存货跌价准备的计提方法计提依据及充分性   （27 字）
```

## 4. 切成 4 字碎片

不做分词，只用滑窗：每 4 个字切一刀，**重叠**地滑过去。27 个字 → 24 个碎片。

| 起始位置 | 碎片 |
| --- | --- |
| 0 | 说明报告 |
| 1 | 明报告期 |
| 2 | 报告期各 |
| … | … |
| 10 | 跌价准备 |
| 11 | 价准备的 |
| 12 | 准备的计 |
| … | … |
| 21 | 计提依据 |
| 22 | 提依据及 |

### 为什么是 4，不是 2、3 或 5

这是**测出来**的，不是拍的。评测口径见 §12，结论：

| 方案 | 改写区间 P@1 | 改写区间 MRR | 全部样本 P@1 | 全部样本 MRR |
| --- | --- | --- | --- | --- |
| 2-gram | 0.268 | 0.326 | 0.655 | 0.693 |
| 3-gram | 0.341 | 0.425 | 0.695 | 0.738 |
| **4-gram** | **0.512** | **0.595** | **0.775** | **0.817** |
| 2+4 各半 | 0.329 | 0.417 | 0.695 | 0.739 |
| 2+3+4 各 1/3 | 0.329 | 0.420 | 0.695 | 0.741 |

「改写区间」= 库里找不到近乎逐字重复的那一档（真正考验算法的场景）。

4-gram 全胜，而且**混合只会更差**：把 2-gram 的分数平均进来，等于把"人人都沾一点"的底层噪声又掺回去。

机制上：碎片越短，越多文件"沾边"。

| n | 全库里至少共享一条碎片的文件占比 |
| --- | --- |
| 2 | **79.4%** |
| 3 | 40.4% |
| 4 | **20.6%** |

（随机抽 2 万条候选、5 条随机查询取平均）

n=2 时你是在跟八成库文件"比相似"，沾边这件事本身没有信息。n=4 时只剩两成，沾边才有意义。

### 为什么重叠切

一处断掉，旁边还在。候选写「计提方法、计提依据」，query 写「计提的方法和依据」：

- `法计提依` 断了（多了"的"）
- 但 `计提方法`、`计提依据` 还在（这两个碎片取自词内部，不受交界影响）

冗余不是浪费，是容错。

## 5. 权重：IDF

每个碎片 g 先在全库数一遍：多少条 query 含它（`df`）。然后

```
w(g) = ln( 1 + N / (1 + df(g)) )        N = 207,305（全库条数）
```

库里从没出现过的碎片取`w = ln(1 + N)`（最高权重，等价于"极其稀有"）。

### 实测：这道题的 24 个碎片

| 碎片 | 含它的文件数 | 占全库 | 权重 w |
| --- | --- | --- | --- |
| `法计提依` | 1 | 0.00% | **11.55** |
| `提依据及` | 23 | 0.01% | 9.06 |
| `提方法计` | 40 | 0.02% | 8.53 |
| `方法计提` | 59 | 0.03% | 8.15 |
| `末存货跌` | 77 | 0.04% | 7.89 |
| `计提依据` | 157 | 0.08% | 7.18 |
| `计提方法` | 614 | 0.30% | 5.82 |
| `存货跌价` | 2,463 | 1.19% | 4.44 |
| `跌价准备` | 3,049 | 1.47% | 4.23 |
| `期各期末` | 2,841 | 1.37% | 4.30 |
| `报告期各` | 13,444 | 6.49% | 2.80 |
| `说明报告` | 18,841 | 9.09% | **2.49** |

三点观察：

1. **权重不是按"像不像关键词"给的，是按"稀不稀"给的。** `存货跌价` 只有 4.44——因为 1.19% 的库都聊过这个话题，它不稀罕。所以它**不是**靠"极稀有"赢的。
2. **真正拿高权重的是"词与词的交界"。** `法计提依`（计提方**法**+**计**提依据）全库只有 1 份。换句话说：单独一个词不构成"这道题的特征"，**词与词连起来的那条少见长串**才构成。人眼看到的是"关键词"，程序看到的是"少见的长组合"。
3. **注意力份额的变化。**

| 碎片 | 不做 IDF（每个 1/24） | 做完 IDF |
| --- | --- | --- |
| 五个万金油（`说明报告`→`期各期末`） | 20.8% | **4.7%** |
| 五个最稀有（`法计提依`→`末存货跌`） | 20.8% | **42%** |

不需要人维护停用词表，权重每次建库时从 20 万条里现数。

## 6. 相似度：余弦 + 覆盖度

### 三个"分量"

一个句子的分量 = 它所有碎片「权重平方」之和。设 A、B 分别是 query 和候选的碎片集合：

```
你的分量   A = Σ ( c_q(g) · w(g) )²
它的分量   B = Σ ( c_d(g) · w(g) )²
共有分量   C = Σ c_q(g) · c_d(g) · w(g)²      只对两边字面完全相同的碎片求和
```

其中`c` 是碎片在句子里出现的次数（绝大多数是 1）。

为什么是"平方"：余弦的分子是点积，两个句子的同一维度相乘就是 `w × w = w²`。**平方不是额外设计，是公式自带的**；副作用是把权重差异放大——线性比 4.444/2.485 = 1.8 倍，平方后 3.2 倍。

### 两个比值

```
cos = C / √(A · B)     ← 分母两边都进：谁写长了谁吃亏
cov = C / A            ← 分母只有提问方：只问"我要的被答了几成"

sim = 0.5 · cos + 0.5 · cov
```

### 展开算一遍

query：`存货跌价准备的计提方法`（11 字，8 个碎片，A = 273.94）

| 候选 | 共有碎片 | 它的分量 B | 共有分量 C | cos | cov | sim |
| --- | --- | --- | --- | --- | --- | --- |
| 一字不差 | 8 / 8 | 273.94 | 273.94 | 1.000 | 1.000 | 1.000 |
| 答全了但很长：请说明存货跌价准备的计提方法及计提依据是否充分 | 8 / 20 | 906.59 | 273.94 | **0.550** | 1.000 | 0.775 |
| 只答一半：说明存货跌价准备的计提是否充分 | 6 / 12 | 352.01 | 179.38 | **0.578** | 0.655 | 0.616 |
| 不相干：说明报告期各期末应收账款周转率下降的原因 | 0 / 17 | 449.93 | 0 | 0 | 0 | 0 |

### 为什么必须两个都要

把上表 cos 那一列单独排名：

```
只答一半的那个  0.578   ← 余弦更高
答全了的那个    0.550
```

**只看余弦，漏答"计提方法、计提依据"的那条会排到前面**——因为它短，分母小。加上覆盖度变成 0.775 vs 0.616，顺序才对。

一句话分工：**余弦问"咱俩说得像不像"，会被长短影响；覆盖度问"我要的你给了几成"，不看长短。**

### 包含关系下的闭式

如果候选把 query 的全部碎片都包含进去，则 C = A，于是 cov 恒为 1，cos = √(A/B)：

```
sim = 0.5 · ( 1 + √(A/B) )
```

| 情况 | cos | cov | sim |
| --- | --- | --- | --- |
| 长度相同 | 1.000 | 1.000 | 1.000 |
| 它长一倍 | 0.707 | 1.000 | 0.854 |
| 它长 3.3 倍（上表第二行） | 0.550 | 1.000 | 0.775 |

**答全之后，分数只由长度比决定，不会一路掉下去。**

### 覆盖度是不对称的

分母永远是**提问方**。所以：

- 它包含你（你问 8 条，它答满还多写 12 条）→ cov = 1.000；
- 你包含它（你问 8 条，它只答了 3 条）→ cov 按比例扣。

方向不能反：**"我问的它答了没有"才算数，"它说的我问了没有"不算数。**

## 7. 长问题的补丁：分句取最大

一条 query 里常塞好几个要求。所以打分前先按句号 / 分号切开：

```
q 按 [。；！？] 切开 → 每段归一化 → 长度 ≥ 12 字的才单独比
每段各自算一个 sim_i
sim = max( sim_整句 , 0.9 × max_i sim_i )
```

0.9 是折扣：整句比不过时，才让分句来救；分句赢了也略低于整句，防止一个短分句"以偏概全"。

---

## 8. 逐字兜底：最长公共子串

```
LCS  = q 和 d 之间连续相同的最长一段（按字，中间断开不算）
lcs  = |LCS| / min( |q|, |d| )
```

分母取短的那一方，语义是"短的那边有多大比例被一字不差地连续抄到"。

为什么需要它：IDF 余弦是"统计上像"，LCS 是"字面上像"。后者对"两家问的是同一套模板"这种情况非常有效，而且用户一眼就能看懂（页面上标黄的就是这些段）。

## 9. 总分

```
score = 0.70 · sim
      + 0.20 · lcs
      + 0.05 · [问题号相同]
      + 0.05 · [章节相同]

若命中的那条被判定为套话（is_boilerplate）：
score = score × 0.55
```

- 两个方括号是 0/1 指示，不是加数；理论满分 1.000。
- **套话**指"核查上述事项并发表明确意见""按照相关规定补充披露"这类跨公司 100% 命中的问句，建库时算好（判据：正文很短且含这些固定说法）。不压住它们，结果会被淹。
- 章节项在"回复体裁"的板块（创业板、深主板）不可信——那些文件里抽出来的"章节"其实是每道题答案内部的小标题（实测有 2,676 个不同取值）。所以前端已经不下发章节筛选，这一项实际很少触发。

### 真实的一条

查询：`说明报告期各期末存货跌价准备的计提方法、计提依据及充分性`（归一化后 27 字）
第一名：候选原文 111 字

| 项 | 值 | 说明 |
| --- | --- | --- |
| cos | 0.211 | 被它 108 个碎片稀释 |
| cov | 0.541 | 我问的被答了五成四 |
| sim | 0.376 | 0.5×0.211 + 0.5×0.541 |
| lcs | 0.407 | 最长连续 11 字 / 27 |
| 问题号 / 章节 | 0 / 0 | 未触发 |
| 套话 | 否 | 不打折 |
| **score** | **0.3447** | 0.70×0.376 + 0.20×0.407 |

（页面显示 0.345。分数普遍不高是正常的：sim 和 lcs 同时接近 1 几乎不可能。）

## 10. 候选不是全库：先粗筛到 6,000 条

20 万条逐条算分要几十秒。实际流程：

```
① 结构化过滤   板块 / 轮次 / 排除套话
② 取碎片       按 df 从小到大排序，最多取 150 个（最稀有的那些）
③ 倒排召回     query_fts MATCH（OR 连接）→ FTS5 bm25 排序 → 截前 6,000 条
④ 精算         对这 6,000 条算 §6~§9 的全部东西
```

为什么不把 bm25 当最终排序：它奖励"命中多 + 文档短"，和我们"答全了也别吃亏"的目标不一致。它只负责**别漏**，排序交给余弦 + 覆盖度。

截断本身是有收益的：15 条随机长问句实测，**平均 2.64 秒 → 0.71 秒**，top5 / top10 结果**完全一致**。

## 11. 输出与展示

- **分组**：用户粘的一整段先按"（1）""①""问题三"这类标记拆成多个最小 query，各自检索、各自成组。这样用户能对上"我的第①问匹配到了什么"。
- **落点面板**：把用户的问题逐字标出三态——
  - 强：与某条命中结果有 **≥ 3 个连续字**逐字相同（4-gram 打分吃得到）；
  - 弱：只在一个"不通用"的 2 字组合上对得上（出现率 ≤ 5%）；
  - 无：对不上。
  弱证据**不参与排序**，只用来解释"为什么这条分数低"。
- **标黄**：所有 ≥ 3 字的极大公共段都标出来，不只是最长那一段。

## 12. 评测方法与读数

**口径**（离线脚本，不在发布包里）：

- 从库里随机取 **200 条** query 当"考题"；
- 在**全库 3.7 万条**（当时的规模）上做**全量排序**，不做任何预筛——测的是打分函数本身；
- 相关性定义：与**另一家公司**的某条 query 之间，**最长可辨公共串** ≥ 10 字，且这条公共串在全库出现 ≤ 400 次（不超过 1% 的库）；
- 按"库里有没有近乎逐字重复"（≥ 24 字相同）分成两档：有 86 条，无 82 条；
  其余 32 条在库里找不到任何合格结果（连 10 字可辨公共串都没有），等于没有标准答案，不计入指标；
- 指标：**P@1**（第一名是否正确）、**MRR@10**（第一个正确结果的倒数名次，前十名内平均）。

读数见 §4 那张表。解读：

- 全部样本 P@1 = **0.775**，MRR = **0.817**（平均落点约第 1.2 名）——有近乎重复的那一档谁都不难，说明"抄得一样"一定能找到；
- 改写区间 P@1 = **0.512**，MRR = **0.595**（平均落点约第 1.7 名）——这才是真实使用场景，一半情况下第一名就正确。

注意 P@1 的上限不是 100%：一道题往往有三五家公司的问法都算合格；也有的题库里确实没有同类，那部分样本不计入。

## 13. 已知局限

1. **连续 4 字不同，就彻底断。** query 写「计提的方法」，候选写「计提方法」：交界碎片全废，只剩词内部那几个还能对上。这是 4-gram 换取排序精度的代价，靠分句和 LCS 部分补偿。
2. **不做同义替换。** 「充分性」和「是否充分」共享的 4 连字很少，容易掉成"弱证据"。这正是落点面板要显示弱证据的原因——让用户知道"算法看到了，只是不敢给分"。
3. **通用话题的权重上不去。** 「存货跌价」这种 1.2% 的库都聊过的话题，IDF 只能给到 4.44；如果整道题都由这类词构成，区分度会下降，要靠同问题号、同章节这类弱先验补。
4. **长输入线性变慢。** 分句比对设了总预算（约 4 万次比对），LCS 设了字符预算，超了就只给靠前的候选补算。极端长文本（几百字）会比短句慢一个数量级。
5. **不建模任何外部先验。** 行业、时间、公司规模都不参与打分。同一条问题在不同年份、不同板块的写法差异，只能靠字面找回来。

## 16. 一句话总结

> 算法并不理解"存货跌价准备"是什么意思。它只做一件事：数这串字在 20 万条问题里有多少人说过。
> 说得越少，就越像这道题独有的东西——**统计上的"稀有"，恰好等于人眼里的"关键词"**。
